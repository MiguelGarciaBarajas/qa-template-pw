# Epic Status Report (`/reporte`, daily, for management)

Use this skill when the user asks for the **daily / boss / management status report** of the
epic (default **PROJ-1**), or asks how that report is generated. Shortcut: **`/reporte`**
(also `/report`).

## Goal

Produce an **epic-level** status report (overall epic health, NOT the user's personal daily
activities) with numbers pulled **live from Jira** and **deltas vs the previous business day**,
emitted as a paste-ready `.txt` and a Word `.docx` with an AI-attribution footer.
**Scope = Bugs/defects only** — Tasks and Stories are excluded from all counts.

## Two-step pipeline (nothing is hand-written)

### Step 1 — Live snapshot (`scripts/fetch-epic-snapshot.ts`)
```bash
npx tsx scripts/fetch-epic-snapshot.ts <YYYY-MM-DD>
```
- Queries Jira REST with JQL `"Epic Link" = PROJ-1`, paginating **every** issue in the epic.
- Aggregates counts by **status**, by **type** (Bug/Task/Story), and a **bug-pipeline** breakdown
  (`closed`, `pipeline`, `activeOpenInProgress`).
- Writes `scripts/epic-live-snapshot-<date>.json` — the day's immutable "photo".

### Step 2 — Report generator (`scripts/generate-status-report-<date>.py`)
```bash
python scripts/generate-status-report-<YYYY-MM-DD>.py
```
- Reads **today's** snapshot **and the previous business-day** snapshot; computes the **deltas**.
- Fills a fixed 6-section template (same shape every day → comparable) and writes:
  - `artifacts/QA_Status_Report_<date>.txt` (paste-ready)
  - `artifacts/QA_Status_Report_<date>.docx` (Word, with the AI footer)

## How to produce a new day's report

1. Fetch today's snapshot: `npx tsx scripts/fetch-epic-snapshot.ts <today>`.
2. **Copy the most recent** `scripts/generate-status-report-<prev>.py` to
   `scripts/generate-status-report-<today>.py` and update the four path constants
   (`SNAP`, `PREV`, `OUT_TXT`, `OUT_DOCX`) and the two dates in the `TXT` header / DOCX footer.
   - `PREV` = the **previous business day** snapshot (skip weekends — e.g. Monday's `PREV` is
     the prior Friday). Ensure that snapshot JSON exists; if not, fetch it first.
3. Run it: `python scripts/generate-status-report-<today>.py`.
4. **Blockers section:** keep section 4 = the tickets currently holding up the QA queue. Pull
   the current blockers (P1/P2 outages or anything blocking live validation) and name them with
   key, priority, status and a one-line symptom + impact. Cross-link related ones.

## Report structure (6 sections)

> **Bugs/defects only.** This report counts only `issuetype = Bug`; **Tasks and Stories are
> excluded** from every count, delta and status breakdown (use the snapshot's `bugCounts` /
> `bugCounts.byStatus`, NOT the full-epic `statusCounts`/`typeCounts`).

1. **Defect health today** — total bugs (+delta), where defects sit (Closed / In Acceptance /
   Performance Test), movement vs last business day. No Task/Story type mix.
2. **QA queue** — bugs Ready for Testing + bugs In Testing.
3. **Defects** — bug totals, closed vs pipeline, confirmed active (Open + In Progress).
4. **BLOCKERS** — tickets blocking the QA queue (name them explicitly with impact).
5. **Current defect status** — the numbered bug status breakdown (Bugs only; no by-type line).
6. **Bug pipeline breakdown** — bug counts per status + active defects.

## Conventions

- **Epic-level, not personal.** This is the epic's overall status, not the user's day.
- **Bugs/defects only.** Count only `issuetype = Bug`; exclude Tasks and Stories from every
  count, delta and status breakdown (use `bugCounts` / `bugCounts.byStatus`).
- **Live + auditable.** Every number comes from the same JQL anyone can run in Jira; the dated
  snapshot JSON is archived so deltas are verifiable.
- **English**, AI-attribution footer: `Generated by QA AI Agent (GitHub Copilot) | Reviewed by:
  the QA owner | Data pulled live from Jira on <date>`.
- **Deltas vs previous business day**, not vs yesterday-calendar (skip weekends).
- **Outputs go to `artifacts/`** — never commit the `.txt`/`.docx`. The daily generator + snapshot
  JSON are also left uncommitted (match the existing `generate-status-report-*.py` files).

## Verify before sending

- Snapshot `total` == sum of `statusCounts` (sanity check the fetch).
- Every delta reads against the correct previous-business-day snapshot.
- Section 4 names the real current blockers with correct priority/status.
